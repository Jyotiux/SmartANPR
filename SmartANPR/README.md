
# SmartANPR: Vehicle Access Management with YOLOv8 & EasyOCR

This project detects vehicles in a video, reads their license plates, and allows integration with a web app to manage access (e.g., for a gate system). The system uses **YOLOv8** for vehicle and license plate detection and **EasyOCR** for reading plate numbers.

---

## Features

1. Detect vehicles (car, motorcycle, bus, truck) from videos.
2. Detect and read license plates.
3. Track vehicles across frames using **SORT** tracker.
4. Export per-frame results to `test.csv`.
5. **Vehicle-level OCR aggregation** — one final plate per tracked vehicle,
   chosen by frequency + confidence across frames, exported to
   `test_aggregated.csv` (see [Improvements](#improvements)).
6. **Conservative OCR preprocessing** to improve plate reads without retraining.
7. Whitelist functionality to allow only authorized vehicles.
8. Simple **Flask** web app to visualize entries and whitelist vehicles.
9. Reproducible **evaluation harness** for OCR accuracy (`eval/`).

## Providing input video

The input video is **not committed** to the repo (kept small/clean). Place your
own clip at `data/sample.mp4` before running — `main.py` reads `./data/sample.mp4`.

## Usage

### Run ANPR on a video

```bash
# Activate virtual environment
source venv/bin/activate        # Windows: .\venv\Scripts\activate

# Run the pipeline (reads ./data/sample.mp4)
python main.py
```

Outputs:
* `output.mp4` — annotated video (falls back to `output.avi` if the codec is unavailable).
* `test.csv` — per-frame results. Each row:
  `frame_nmr, car_id, car_bbox, license_plate_bbox, license_plate_bbox_score, license_number, license_number_score`.
* `test_aggregated.csv` — **one final plate per vehicle**. Each row:
  `car_id, license_plate, aggregate_score, best_frame_score, num_votes, num_reads`.

### Run the Web App

```bash
cd web_app
pip install flask  # if not already installed
python app.py
```

* Open `http://127.0.0.1:5000` in a browser.
* Reads `test.csv` and `whitelist.csv`, renders `templates/dashboard.html`, and
  shows which detected vehicles are authorized.

---

## Web App Integration

* `test.csv` → Stores all detected license plate numbers.
* `whitelist.csv` → Stores authorized license plate numbers.
* Flask app reads both CSVs and shows which vehicles are allowed.
* Can be extended for a **gate system**:

  * Detect vehicle in real-time.
  * Check license plate against whitelist.
  * Open gate if authorized.

## Improvements

Two targeted OCR improvements were made on top of the baseline. **No model was
retrained or replaced** — the YOLO + SORT detection/tracking pipeline is
unchanged, and the `test.csv` format is preserved.

1. **Vehicle-level OCR aggregation.** OCR produces many reads for the same
   tracked `car_id` across frames. Reads are now collected per vehicle and one
   final plate is chosen by **frequency first, then summed confidence, then best
   single-frame confidence**, so a single low-confidence read cannot overwrite a
   consistent higher-confidence result. Result is written to
   `test_aggregated.csv` (the per-frame `test.csv` is untouched).

2. **Conservative OCR preprocessing.** `read_license_plate()` tries the crop
   **as received first** (baseline behavior preserved), then a lightly enhanced
   variant (upscale small crops → grayscale → CLAHE contrast → Otsu threshold),
   and keeps the highest-confidence compliant read. Because the original crop is
   always tried, already-good crops cannot be made worse. No new dependencies.

See [`docs/CHANGELOG.md`](docs/CHANGELOG.md) for the full change history and
[`docs/PROJECT_BASELINE.md`](docs/PROJECT_BASELINE.md) for the original baseline audit.

## Evaluation

A small, reproducible OCR evaluation harness lives in [`eval/`](eval/). It runs
the existing OCR path (no algorithm changes) on a **fixed, hand-labeled** set so
the baseline and improvements are compared on the same samples.

```bash
python eval/evaluate_ocr.py \
    --video data/sample.mp4 \
    --ground-truth eval/ground_truth.csv \
    --out-dir eval/results
```

Ground truth must be labeled by hand (see [`eval/README.md`](eval/README.md)) —
`test.csv` is model output and cannot be used as truth. Metrics: exact-match
accuracy, character-level accuracy, read rate, and OCR latency/FPS, with
`correct` / `wrong` / `missing` outcomes distinguished. Results are recorded in
[`docs/BASELINE_RESULTS.md`](docs/BASELINE_RESULTS.md).
